01

Activer Hyper-V & créer une VM

Hyper-V est déjà dans Windows — il suffit de l'allumer. C'est l'hyperviseur qui portera tout le labo Windows Server du parcours.

Ce que tu sauras faire

  • Vérifier qu'un poste peut héberger Hyper-V (édition de Windows, virtualisation matérielle) puis activer la fonctionnalité.
  • Créer une VM de génération 2 avec New-VM et contrôler son état avec Get-VM.

Avant de commencer : aucun prérequis · 30 min · un poste Windows 11 Pro, Entreprise ou Éducation dont la virtualisation (Intel VT-x / AMD-V) est activée dans le BIOS/UEFI.

Pourquoi un hyperviseur sur son propre poste

Un technicien qui apprend Windows Server a besoin de plusieurs machines : un contrôleur de domaine, un serveur de fichiers, un client. Acheter ou prêter trois ordinateurs n'est pas réaliste, et casser un serveur réel pour s'entraîner est exclu. Un hyperviseur fait tourner ces machines simulées sur un seul poste : on les crée, on les casse, on les refait.

Hôte, invité et console : le vocabulaire d'Hyper-V

Hyper-V est l'hyperviseur de Microsoft, livré avec Windows comme fonctionnalité facultative : il n'y a rien à télécharger, il faut l'activer. Trois mots suffisent pour la suite.

TermeCe que c'estExemple du module
HôteL'ordinateur réel qui fait tourner Hyper-VTon poste Windows 11 Pro
Invité (VM)Une machine virtuelle : un ordinateur simulé avec son propre systèmeSRV-FILE01
Hyper-V ManagerLa console graphique qui crée et pilote les VM de l'hôteMenu New → Virtual Machine

Deux conditions pour que l'activation fonctionne : une édition Windows qui contient Hyper-V (Pro ou Entreprise ; Famille est exclue), et un processeur 64 bits avec virtualisation et SLAT.

Source : Microsoft Learn — Install Hyper-V in Windows and Windows Server (prérequis : Windows 10/11 Pro ou Enterprise, processeur 64 bits avec SLAT ; pas de Hyper-V sur Famille).

    La VM existe, éteinte, sans système : elle attend une ISO (chapitre 03).

Avant de cocher : deux prérequis

Hyper-V n'existe que dans les éditions Pro, Entreprise et Éducation de Windows 11 (sous Windows 10 : Pro et Entreprise ; et dans Windows Server) : pas dans Windows Famille. Et la virtualisation matérielle (Intel VT-x / AMD-V) doit être activée dans le BIOS/UEFI du poste.

La même chose en PowerShell

PowerShell (admin) — hôte
# Activer Hyper-V (redémarrage demandé ensuite)
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

# Créer une VM génération 2 : 8 Go de RAM au démarrage, un disque neuf de 60 Go
New-VM -Name "SRV-FILE01" -Generation 2 -MemoryStartupBytes 8GB -Path "C:\VM" `
       -NewVHDPath "C:\VM\SRV-FILE01\SRV-FILE01.vhdx" -NewVHDSizeBytes 60GB -SwitchName "Default Switch"

Vérifier

La VM existe-t-elle, avec la bonne génération ?

PowerShell — hôte
Get-VM -Name SRV-FILE01 | Select-Object Name, State, Generation

Sortie attendue

Name       State Generation
----       ----- ----------
SRV-FILE01   Off          2

Get-VM inconnu : le module PowerShell Hyper-V n'est pas installé (fonctionnalité pas activée, ou poste pas redémarré). Generation 1 : la VM est à recréer, la génération ne se change pas.

Lancer une console en administrateur

Depuis Win + R, valider avec Ctrl + Maj + Entrée au lieu de Entrée : le programme démarre directement en tant qu'administrateur.

À toi — une seconde VM de test

Crée en PowerShell une VM génération 2 nommée SRV-TEST01 : 4 Go de mémoire au démarrage, un disque neuf de 40 Go, rangée sous C:\VM, branchée sur le Default Switch. Puis affiche son nom, son état et sa génération.

Voir la solution

On reprend la commande du chapitre en changeant le nom, la mémoire et la taille du disque :

New-VM -Name "SRV-TEST01" -Generation 2 -MemoryStartupBytes 4GB -Path "C:\VM" `
       -NewVHDPath "C:\VM\SRV-TEST01\SRV-TEST01.vhdx" -NewVHDSizeBytes 40GB -SwitchName "Default Switch"
Get-VM -Name SRV-TEST01 | Select-Object Name, State, Generation

Attendu : la VM est Off, génération 2. Variante des commandes du module, adaptée sans exécution supplémentaire : reconstitué, non testé.

Variante sans indice

Une collègue veut suivre ce module sur son portable Windows 11 Famille. Que lui réponds-tu, et quelles sont ses options ?

Voir la solution

Hyper-V n'existe pas dans l'édition Famille : l'activation est impossible. Elle peut passer à une édition qui l'inclut (Pro, Entreprise ou Éducation), ou utiliser un autre poste Windows Pro. Contrôler aussi que la virtualisation est active dans le BIOS/UEFI.

Quand ça casse — la commande est inconnue

Tu viens de cocher Hyper-V dans Fonctionnalités Windows et de fermer la fenêtre. Dans une console administrateur, Get-VM répond que la commande est inconnue. Hyper-V Manager n'apparaît pas encore dans le menu Démarrer.

Voir la démarche et la cause

Démarche : vérifier que la fonctionnalité est bien activée et si le poste a redémarré depuis. Cause : le module PowerShell Hyper-V n'est chargé qu'après le redémarrage demandé par l'activation. Correctif : redémarrer le poste, puis relancer Get-VM.

À retenir

  • Hyper-V se active (Pro, Entreprise, Éducation) ; il faut la virtualisation matérielle et un redémarrage.
  • New-VM -Generation 2 crée la VM ; Get-VM contrôle son nom, son état et sa génération.
  • La génération se choisit à la création : chapitre suivant.

02

Régler la VM : génération, RAM, CPU, boot

Quatre réglages décident du confort du labo. Un seul est irréversible : la génération.

Ce que tu sauras faire

  • Choisir la génération d'une VM d'après le système invité et son mode de démarrage.
  • Régler mémoire fixe, 2 processeurs virtuels et ordre de démarrage, puis choisir le modèle de démarrage sécurisé d'une VM Linux.

Avant de commencer : chapitre Activer Hyper-V & créer une VM · 30 min · Hyper-V actif sur l'hôte.

Pourquoi régler avant d'installer

Une VM créée à la va-vite se paie plus tard : un serveur qui rame parce qu'il a trop ou trop peu de processeurs, une installation qui refuse de démarrer sur l'ISO, ou une génération qui ne convient pas au système voulu. La génération, elle, ne se corrige pas : il faut recréer la VM. On règle donc avant d'installer.

Les deux générations et ce qui les distingue

La génération décide du matériel virtuel offert à la VM. Elle est une propriété de la VM, pas du disque, et ne peut plus changer après la création. Microsoft recommande la génération 2 sauf si le système invité, le disque préparé ou le mode de démarrage ne la supportent pas.

Génération 1Génération 2
MicroprogrammeBIOSUEFI (démarrage sécurisé, activé par défaut)
Démarrer depuisDisque ou DVD sur contrôleur IDEDisque VHDX ou ISO sur contrôleur SCSI
Volume de démarrage max (VHDX)2 To64 To
Windows 11 invitéNonOui
Windows Server 2012 à 2025 invitéOuiOui

Deuxième notion : la mémoire dynamique laisse Hyper-V ajuster la mémoire d'une VM selon sa charge, entre un minimum et un maximum. Le module la désactive pour un serveur : on lui donne une valeur fixe. Enfin, un invité Linux qui garde le démarrage sécurisé doit utiliser le modèle Microsoft UEFI Certificate Authority.

Source : Microsoft Learn — Should I create a generation 1 or 2 virtual machine in Hyper-V? (tableaux de support, tailles de volume, modèle UEFI CA pour Linux) et Hyper-V Features and Terminology Overview (mémoire dynamique).

Trois VM à créer : quelle génération pour chacune ?

    Les deux générations conviennent : on prend la 2

    Le tableau de support accepte Windows Server 2025 dans les deux générations ; la génération 2 apporte UEFI et démarrage sécurisé.

  3. VM 3 · Windows 11

    Le tableau tranche seul

    Windows 11 n'est pas supporté en génération 1 : la question ne se pose pas.

    Choix : génération 2, imposée.

Génération 1 ou 2 ?

Génération 1

Équivalent BIOS. Pour les OS anciens ou 32 bits.

Génération 2

Équivalent UEFI. Démarrage sécurisé, boot plus rapide, disques SCSI. C'est le choix par défaut ici.

Choix définitif

La génération se fixe à la création et ne peut plus être changée ensuite. Se tromper oblige à recréer la VM.

Variante sans indice

Un collègue a créé une VM en génération 1 pour installer Windows 11, « parce que la génération 1 est plus compatible ». Que lui dis-tu, et que doit-il faire ?

Voir la solution

Windows 11 n'est pas supporté en génération 1, et la génération ne se change pas après la création : il faut recréer la VM en génération 2.

Quand ça casse — l'hôte rame avec trois VM

Tu as créé trois VM avec l'assistant sans toucher à leurs paramètres. Dès qu'elles tournent ensemble, l'hôte et les VM deviennent lents. Dans les paramètres, rien ne ressemble à une erreur évidente.

Voir la démarche et la cause

Démarche : ouvrir les paramètres d'une VM et comparer les ressources attribuées à ce que le module recommande. Cause probable : l'assistant a créé chaque VM avec 12 processeurs virtuels (valeur relevée au TP) : trop de vCPU prive l'hôte et les autres VM. Correctif : passer chaque VM à 2 processeurs, mémoire fixe.

À retenir

Génération 2 (définitive), mémoire fixe, 2 vCPU, ordre de démarrage dans Microprogramme. Pour un invité Linux : le modèle de démarrage sécurisé Microsoft UEFI Certificate Authority.

Question éclair

Tu crées une VM génération 2 pour installer Debian depuis l'ISO officielle. Au démarrage, l'écran du microprogramme refuse de booter sur le DVD et signale que l'image n'est pas autorisée par le démarrage sécurisé. Que fais-tu ?

Le modèle par défaut (Microsoft Windows) n'accepte que les chargeurs Windows. Debian 10 à 12 et Ubuntu sont signés via le shim par l'autorité Microsoft UEFI Certificate Authority : on choisit ce modèle et on garde le démarrage sécurisé actif. Le désactiver ne sert que pour une distribution non signée.

03

Installer Windows Server dans la VM

L'installation elle-même est classique — trois détails la font rater quand on ne les connaît pas.

Ce que tu sauras faire

  • Démarrer une VM sur l'ISO et installer Windows Server 2025 Standard (Desktop Experience).
  • Réarmer la période d'évaluation et activer la session étendue.
  • Diagnostiquer un écran d'installation qui ne propose aucun disque.

Avant de commencer : chapitre Régler la VM · 30 min · une VM réglée et une ISO de Windows Server 2025.

Pourquoi l'installation mérite un chapitre

C'est le geste que le technicien répète le plus : chaque serveur commence par là. Le rater coûte du temps : si on manque la courte fenêtre de démarrage sur le DVD, la VM démarre sur un disque vide et il faut la redémarrer ; une mauvaise édition oblige à tout refaire.

04

Configurer le serveur au premier démarrage

Une check-list à dérouler dans l'ordre — le renommage en dernier, parce qu'il redémarre la machine.

Ce que tu sauras faire

  • Dérouler la check-list de premier démarrage dans le bon ordre, en justifiant que le renommage vient en dernier.
  • Fixer l'adresse IPv4 d'un serveur, autoriser le Bureau à distance (port 3389) et décider quand couper le pare-feu.

Avant de commencer : chapitre Installer Windows Server · 30 min · un Windows Server 2025 fraîchement installé dans une VM.

Pourquoi un serveur ne se configure pas « au fil de l'eau »

Un serveur neuf est configuré pour un poste quelconque : adresse automatique, mauvais fuseau, nom aléatoire. Les autres machines doivent pouvoir le retrouver à une adresse stable, et chaque réglage oublié se paie plus tard au milieu d'un TP. D'où une liste courte, dans un ordre qui évite d'être interrompu par un redémarrage.

Les réglages, leur raison et leur piège

RéglagePourquoiPiège
Adresse IPv4 fixeUn serveur doit avoir une adresse prévisible : les autres machines le joignent par elleRester en DHCP, l'adresse peut changer
Bureau à distance (RDP)Administrer le serveur sans passer par la console de la VM ; port 3389 par défautOublier d'autoriser les connexions à distance
Pare-feuFiltre le trafic ; en labo, le couper évite de chercher un blocage en déboguant un TPLe laisser coupé en dehors du labo
Windows UpdateDownload updates only évite un redémarrage en plein TPS'étonner que rien ne s'installe
RenommageDonne son vrai nom au serveur (WS01)Il redémarre la machine : on le fait en dernier

Le pare-feu en labo

Invite de commandes (admin)

Réservé au labo

Couper le pare-feu fait gagner du temps quand on débogue un TP, et uniquement dans ce cadre. Sur un serveur réel, on ouvre les ports nécessaires — on ne désarme pas la machine.

Sysprep : fabriquer une image réutilisable

Réinstaller Windows Server à chaque TP prend une demi-heure. Sysprep permet de le faire une fois, puis de repartir de cette image pour toutes les VM suivantes.

Ce que tu sauras faire

  • Expliquer ce que fait Generalize et pourquoi une image généralisée ne se rallume pas.
  • Fabriquer une image : lancer sysprep.exe (Generalize + Shutdown), isoler le .vhdx dans C:\PARENT.

Avant de commencer : chapitre Configurer le serveur au premier démarrage · 40 min · une VM WS01 installée et configurée.

Pourquoi fabriquer une image une seule fois

Réinstaller et reconfigurer un serveur prend une demi-heure à chaque TP. En fabriquant une image propre, on repart d'elle pour toutes les VM suivantes. Mais on ne peut pas cloner une installation telle quelle : deux machines ne doivent pas partager le même identifiant. Sysprep règle ce problème.

Généraliser : ce qui disparaît, ce qui reste

Le SID est l'identifiant de sécurité unique d'une installation Windows. Generalize retire les informations propres à la machine, dont ce SID et les périphériques configurés (les pilotes restent sur le disque). Au démarrage suivant, Windows passe par l'OOBE, l'écran de première configuration, et se personnalise : nouveau SID, nom, réglages.

VM de référence avant SysprepImage généralisée
IdentitéSID propre à la machineSID retiré
Peut démarrer ?OuiUne seule fois : le premier démarrage la personnalise et consomme la généralisation
UsageSe configureSe copie, ne se démarre plus

Règle : une image généralisée est faite pour un seul premier démarrage, celui de chaque VM qui en dérive. Sysprep se relance sur une même image jusqu'à 1001 fois au plus.

Source : Microsoft Learn — Sysprep (Generalize) a Windows installation (SID et périphériques retirés, pilotes conservés, limite de 1001 exécutions).

Déployer des VM en série (disque parent)

Un disque de différenciation ne stocke que les écarts par rapport au disque parent. Créer une nouvelle VM revient alors à créer un fichier quasi vide — quelques secondes au lieu d'une installation complète.

Ce que tu sauras faire

  • Expliquer ce que stocke un disque de différenciation et pourquoi le disque parent ne doit jamais changer.
  • Déployer une VM depuis l'image Sysprep et vérifier la chaîne parent / enfant avec Get-VHD.
  • Décider entre un disque de différenciation et un disque à taille dynamique selon la durée de vie de la VM.

Avant de commencer : chapitre Sysprep · 40 min · l'image C:\PARENT\TEST-SYSPREP.vhdx.

Pourquoi ne pas copier l'image à chaque VM

Un labo de dix VM issues de la même image, c'est dix fois les mêmes gigaoctets recopiés. Un disque de différenciation ne stocke que ce qui change : créer une VM revient à créer un fichier presque vide, en quelques secondes, et l'image d'origine reste intacte.

FichierRôleRègle

Un enfant enregistre des blocs par rapport à un état précis du parent : si le parent change, les enfants ne correspondent plus. Pour mettre l'image à jour, on crée une nouvelle image et on y rattache les futures VM.

Choisir son commutateur virtuel

Le Gestionnaire de commutateur virtuel décide de qui peut parler à qui. Trois types, trois périmètres de plus en plus fermés.

Ce que tu sauras faire

  • Choisir entre commutateur externe, interne et privé selon ce que le labo doit pouvoir joindre.
  • Créer un commutateur avec New-VMSwitch et le raccorder aux VM.
  • Décrire le réseau du lab Orion (commutateur interne, hôte passerelle, NAT).

Avant de commencer : chapitre Déployer des VM en série · 30 min · deux VM prêtes et une console PowerShell administrateur sur l'hôte.

Pourquoi le réseau d'un labo se choisit avec soin

Un labo qui monte son propre DHCP et son propre DNS ne doit pas les laisser répondre sur le réseau de la maison ou de l'école : les ordinateurs voisins pourraient y prendre leur adresse. En revanche, des VM sans aucune sortie ne peuvent pas télécharger leurs mises à jour. Le commutateur virtuel décide de ce périmètre.

Externe, interne, privé : trois périmètres

Un commutateur virtuel est un switch de couche 2 logiciel, dans l'hôte : chaque VM y branche une carte réseau virtuelle. Hyper-V en propose trois types, choisis à la création.

TypeQui communiqueUsage
ExterneVM ↔ hôte ↔ réseau physique ↔ InternetLe commutateur se branche sur la carte physique de l'hôte ; l'hôte garde l'accès par une carte vEthernet (option Autoriser le système d'exploitation de gestion à partager). Quand les VM doivent être sur le réseau réel.
InterneVM ↔ VM ↔ hôteL'hôte reçoit une carte virtuelle vEthernet (nom) sur ce commutateur : VM et hôte se parlent, sans accès extérieur… sauf si l'hôte fait du NAT (lab Orion).
PrivéVM ↔ VM uniquementLe périmètre le plus fermé. Idéal pour un labo de domaine isolé.

Deux précisions : on peut changer le type d'un commutateur existant, mais cela touche toutes les VM qui y sont connectées ; et une carte réseau virtuelle ne change pas de type, on en ajoute une autre sur le bon commutateur.

Source : Microsoft Learn — Plan for Hyper-V networking in Windows Server (les trois types de commutateurs, changement de type, option de partage avec l'hôte).

Exemple travaillé

Le réseau du lab Orion : pourquoi interne + NAT

  1. Étape 1 · le besoin

    Trois contraintes

    Les VM doivent se parler et parler à l'hôte ; elles doivent sortir sur Internet pour leurs mises à jour ; le DHCP du lab ne doit jamais répondre sur le réseau physique.

    Un externe est exclu (le DHCP du lab répondrait aux autres PC) ; un privé est exclu (aucune sortie).

  2. Étape 2 · le choix

    Un commutateur interne

    Il relie VM et hôte, sans toucher le réseau physique. L'hôte y reçoit une carte virtuelle vEthernet (LABOPS) et sert de passerelle.

    Réseau du lab : 172.16.50.0/24, hôte en 172.16.50.1.

  3. Étape 3 · la sortie

    Du NAT sur l'hôte

    Une traduction d'adresses (New-NetNat) fait sortir les VM par l'hôte : elles accèdent à Internet, personne n'entre, et aucune trame du lab n'atteint le réseau physique.

    Les trois commandes figurent dans le terminal plus bas.

1
Créer le commutateur

Hyper-V Manager → Gestionnaire de commutateur virtuel → type Privé → nom LAN1 → Appliquer.

2
Le raccorder aux VM

Dans les paramètres de chaque machine, sélectionner la nouvelle carte à la place du Default Switch.

Le réflexe du labo AD

Un domaine de test se monte sur un commutateur privé : le DHCP et le DNS du labo ne risquent alors pas de répondre sur le réseau de la maison ou de l'école. Si les VM ont besoin d'Internet ponctuellement (mises à jour), on leur ajoute une seconde carte sur un commutateur externe plutôt que de tout basculer. Autre solution, celle du lab Orion : un commutateur interne avec du NAT sur l'hôte (New-NetNat) — les VM sortent sur Internet, personne n'entre.

PowerShell (admin) — le réseau du lab Orion
New-VMSwitch -Name "LABOPS" -SwitchType Internal
New-NetIPAddress -InterfaceAlias "vEthernet (LABOPS)" -IPAddress 172.16.50.1 -PrefixLength 24   # l'hôte = passerelle
New-NetNat -Name "LABOPS-NAT" -InternalIPInterfaceAddressPrefix 172.16.50.0/24

Vérifier

Constat d'interface : dans le Gestionnaire de commutateur virtuel d'Hyper-V Manager, LABOPS figure dans la liste, de type interne ; sur l'hôte, la carte vEthernet (LABOPS) existe avec l'adresse 172.16.50.1. Une VM raccordée à ce commutateur et configurée dans 172.16.50.0/24 joint l'hôte.

La carte vEthernet (LABOPS) est introuvable : le commutateur n'est pas de type interne, ou New-NetIPAddress vise un autre nom de carte (-InterfaceAlias).

À toi de taper

Crée en PowerShell un commutateur virtuel privé nommé LAN1.

Voir la solution

Question éclair

Ton lab AD a son propre DHCP. Les VM doivent télécharger des mises à jour, mais le DHCP du lab ne doit en aucun cas répondre aux PC de la maison. Quel commutateur ?

Interne + New-NetNat : les VM sortent par l'hôte (traduction d'adresses), mais aucune trame du lab n'atteint le réseau physique — le DHCP reste confiné. C'est le choix du lab Orion.

Variante sans indice

Tu veux que trois VM échangent des fichiers avec ton poste hôte, sans qu'aucune ne puisse sortir vers Internet ni vers le réseau de la maison. Quel type de commutateur, et faut-il du NAT ?

Voir la solution

Un commutateur interne : VM et hôte se parlent par la carte vEthernet de l'hôte. Pas de New-NetNat : c'est lui qui ouvrirait la sortie vers Internet.

Quand ça casse — la maison reçoit des adresses étranges

Tu as branché ton lab AD (avec son propre DHCP) sur le réseau. Depuis, des ordinateurs de la maison obtiennent des adresses qui ne sont pas celles de la box, et perdent leur accès à Internet.

Voir la démarche et la cause

Démarche : regarder à quel commutateur les VM du lab sont raccordées. Cause probable : un commutateur externe place les VM sur le réseau de la maison : le DHCP du lab répond aux PC de la famille. Correctif : raccorder le lab à un commutateur privé, ou interne avec du NAT sur l'hôte si les VM doivent sortir.

À retenir

  • Externe : VM, hôte, réseau physique ; interne : VM et hôte ; privé : VM seulement.
  • New-VMSwitch -Name "…" -SwitchType Private | Internal ; un externe se branche sur une carte avec -NetAdapterName.
  • Lab AD : privé, ou interne + New-NetNat pour la sortie (lab Orion, 172.16.50.0/24). Jamais le DHCP du lab sur le réseau de la maison.

Points de contrôle et vérifications

Un point de contrôle (checkpoint) fige l'état d'une VM pour pouvoir y revenir : c'est l'outil idéal d'un lab — tester, casser, revenir. À condition de savoir ce qu'il n'est pas : une sauvegarde.

Ce que tu sauras faire

  • Choisir entre point de contrôle standard et production selon le besoin.
  • Figer, lister, restaurer et supprimer un point de contrôle en PowerShell.
  • Expliquer pourquoi un point de contrôle n'est pas une sauvegarde.

Avant de commencer : chapitre Déployer des VM en série (disques parent / enfant) · 30 min · une VM, ici SRV-FILE01.

Pourquoi figer l'état d'une VM

Avant de tester une stratégie de groupe risquée ou une mise à jour, on veut pouvoir revenir en arrière en quelques secondes si tout casse. C'est le grand avantage de la virtualisation pour un lab : tester, casser, revenir.

Standard ou production, et ce que le point de contrôle n'est pas

Standard

Capture le disque et la mémoire : on revient exactement à l'instant figé, applications ouvertes. Le choix du lab, pour revenir avant une manipulation risquée.

Production (par défaut)

S'appuie sur les sauvegardes internes de l'OS invité (VSS sous Windows) : la VM revient comme après un arrêt propre, sans la mémoire. Plus sûr pour les applications et les bases de données.

Techniquement, un point de contrôle est un fichier .avhdx posé à côté du .vhdx de la VM. Le supprimer par la commande dédiée fusionne ce fichier dans le disque principal ; on ne supprime jamais un .avhdx à la main.

Source : Microsoft Learn — Using checkpoints (types standard et production, production par défaut, fichiers .avhdx, suppression et fusion ; un instantané n'est pas une sauvegarde complète).

Exemple travaillé

Quel type de point de contrôle pour quelle manipulation ?

  1. Cas 1 · tester une GPO risquée sur SRV-FILE01

    Standard

    On veut revenir à l'instant exact, applications ouvertes : le standard capture disque et mémoire.

    Choix : standard.

  2. Cas 2 · une VM qui porte une base de données

    Production

    Il s'appuie sur les sauvegardes internes de l'invité (VSS) : la VM revient comme après un arrêt propre, plus sûr pour les applications.

    Choix : production.

  3. Cas 3 · protéger la VM d'une panne du disque de l'hôte

    Ni l'un ni l'autre

    Le point de contrôle vit sur le même stockage que le disque : si le disque de l'hôte meurt, tout part. Il faut une vraie sauvegarde, sur un autre support.

    Choix : une sauvegarde, pas un point de contrôle.

PowerShell — hôte Hyper-V
Checkpoint-VM -Name SRV-FILE01 -SnapshotName "Avant DFS"          # figer
Get-VMSnapshot -VMName SRV-FILE01                                  # lister
Restore-VMSnapshot -VMName SRV-FILE01 -Name "Avant DFS" -Confirm:$false   # revenir
Remove-VMSnapshot -VMName SRV-FILE01 -Name "Avant DFS"             # supprimer = fusionner

Vérifier

Après Checkpoint-VM, la commande Get-VMSnapshot -VMName SRV-FILE01 liste le point de contrôle Avant DFS ; après Remove-VMSnapshot, il n'y figure plus et le fichier .avhdx correspondant a été fusionné.

Le point n'apparaît pas dans la liste : le nom donné à -SnapshotName n'est pas celui interrogé, ou la VM visée n'est pas la bonne (-VMName).

Pas une sauvegarde

Un point de contrôle vit à côté du disque (fichier .avhdx) et sur le même stockage : si le disque de l'hôte meurt, tout part. Ce n'est pas une sauvegarde. Sur un contrôleur de domaine, Windows Server détecte le retour en arrière (identifiant de génération de la VM, depuis 2012) et se protège ; Microsoft déconseille malgré tout de s'en servir comme sauvegarde : on restaure une vraie sauvegarde de l'annuaire.

À toi — figer puis revenir

Avant d'appliquer une GPO de test, fige SRV-FILE01 sous le nom « Avant GPO ». La GPO se passe mal : reviens en arrière sans qu'une confirmation soit demandée, puis supprime le point de contrôle.

Voir la solution
Checkpoint-VM -Name SRV-FILE01 -SnapshotName "Avant GPO"
Restore-VMSnapshot -VMName SRV-FILE01 -Name "Avant GPO" -Confirm:$false
Remove-VMSnapshot -VMName SRV-FILE01 -Name "Avant GPO"

Mêmes cmdlets que dans le terminal ci-dessus, avec un autre nom de point de contrôle (reconstitué, non testé).

Variante sans indice

Un collègue veut garder un point de contrôle d'un contrôleur de domaine comme « sauvegarde de l'annuaire ». Que lui réponds-tu ?

Voir la solution

Un point de contrôle n'est pas une sauvegarde : il vit sur le même stockage que la VM. Sur un contrôleur de domaine, Windows Server détecte le retour en arrière et se protège, mais Microsoft déconseille d'en faire une sauvegarde : on restaure une vraie sauvegarde de l'annuaire.

Quand ça casse — le disque de l'hôte se remplit

Le dossier de SRV-FILE01 grossit sans cesse. À côté du .vhdx, plusieurs fichiers .avhdx s'accumulent. Un collègue propose de les supprimer à la main dans l'explorateur pour libérer de la place.

Voir la démarche et la cause

Démarche : lister les points de contrôle avec Get-VMSnapshot -VMName SRV-FILE01. Cause : des points de contrôle gardés « au cas où » allongent la chaîne de disques ; chaque .avhdx en est un. Correctif : ne pas toucher aux fichiers ; supprimer les points de contrôle devenus inutiles avec Remove-VMSnapshot, qui fusionne leur contenu dans le disque principal.

À retenir

Un point de contrôle avant chaque manipulation risquée du lab, supprimé ensuite pour ne pas allonger la chaîne de disques. Get-VHD (chapitre 06) pour vérifier qu'un disque enfant retrouve son parent.

Question éclair

SRV-FILE01 a un point de contrôle de la veille. Le SSD de l'hôte, qui porte tous les fichiers de la VM, tombe en panne. Que peux-tu récupérer grâce au point de contrôle ?

Un point de contrôle protège d'une mauvaise manipulation, pas d'une panne matérielle : il dépend du disque parent et vit sur le même stockage. Contre la panne, il faut une sauvegarde sur un autre support (module DPM).
